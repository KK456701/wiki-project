## 1. 状态机定义

异常排查是一个严格顺序状态机，程序负责关卡判定，模型只在允许的步骤解释证据或草拟 SQL。

### 1.2 status 与 currentStep 对照表

| status | currentStep | 说明 |
|--------|-------------|------|
| `WAITING_CALIBER_CONFIRMATION` | `CALIBER_CONFIRMATION` | 等待确认口径 |
| `IN_PROGRESS` | `GATE_1_SCHEMA` | 数据结构校验 |
| `IN_PROGRESS` | `GATE_2_EVENT` | 事件与抽取校验 |
| `IN_PROGRESS` | `GATE_3_VALUE` | 数据可用性校验 |
| `GATES_PASSED` | `CASE_INPUT` | 三门全过，等待案例 |
| `WAITING_CASE_CALIBER_CONFIRMATION` | `CASE_CALIBER_CLARIFICATION` | 等待确认案例口径 |
| `IN_PROGRESS` | `CASE_INVESTIGATION` | 案例排查中 |
| `CAUSE_CONFIRMED` | `CHANGE_PROPOSAL` | 原因已确认 |
| `CANDIDATE_READY` | `SHADOW_TRIAL` | 候选 SQL 就绪 |
| `SHADOW_PASSED` | `DRAFT_SAVE` | 影子试跑通过 |
| `SHADOW_FAILED` | `SHADOW_TRIAL` | 影子试跑失败 |
| `CANDIDATE_FAILED` | `CASE_INVESTIGATION` | 候选 SQL 构建失败，回到排查 |
| `WAITING_EXTERNAL_FIX` | `CHANGE_PROPOSAL` | 等待外部修复 |
| `DRAFT_SAVED` | `COMPLETED` | 草稿已保存 |
| `COMPLETED` | `COMPLETED` | 已确认正确并关闭 |
| `DRAFT_BASELINE_EXPIRED` | `COMPLETED` | 草稿基线过期 |
| `DRAFT_REVALIDATED` | `COMPLETED` | 草稿重新验证通过 |
| `DRAFT_REVALIDATION_FAILED` | `COMPLETED` | 草稿重新验证失败 |

## 2. Gate 关卡结果结构

### 2.1 通用 Gate Result 结构

每次执行 Gate 后，结果追加到 `gateResults` 数组，按 gate 编号排序。

```json
{
  "gate": 1,
  "name": "数据结构校验",
  "status": "PASSED | BLOCKED",
  "errorCode": "MISSING_TABLE | MISSING_COLUMN | LINEAGE_xxx | null",
  "message": "人类可读的消息",
  "repairSuggestion": "修复建议 | null",
  "facts": { ... }
}
```

### 2.2 Gate 1 详情（`facts` 字段）

从 [`BatchDataInitializationValidator`](backend-java/src/main/java/com/hospital/wikiagent/agent/initialization/BatchDataInitializationValidator.java) 的 `toTraceOutput()` 输出，包含：

| 字段 | 说明 |
|------|------|
| `profiles` | 每个口径的校验决策 |
| `missingTables` | 缺失的表名列表 |
| `missingColumns` | 缺失的字段列表（含所属表） |
| `lineageErrors` | 血缘解析错误 |
| `decision` | `RUNNABLE` / `NO_SAMPLE` / `BLOCKED_TABLE` / `BLOCKED_COLUMN` / `BLOCKED_LINEAGE` |

### 2.3 Gate 2 详情（`facts` 字段）

从 [`DiagnosisEventGateService`](backend-java/src/main/java/com/hospital/wikiagent/agent/diagnosis/DiagnosisEventGateService.java) 的 `run()` 输出，包含：

| 字段 | 说明 |
|------|------|
| `executionEvidence.numeratorCount` | 分子计数 |
| `executionEvidence.denominatorCount` | 分母计数 |
| `executionEvidence.resultValue` | 计算结果 |
| `executionEvidence.overviewSqlHash` | 概览 SQL 哈希（后续明细对账使用） |
| `executionEvidence.status` | 执行状态 |
| `executionEvidence.sampleCount` | 样本量 |

### 2.4 Gate 3 详情（`facts` 字段）

从 [`DiagnosisValueGateService`](backend-java/src/main/java/com/hospital/wikiagent/agent/diagnosis/DiagnosisValueGateService.java) 的 `run()` 输出：

| 字段 | 说明 |
|------|------|
| `status` | `PASSED` / `BLOCKED` |
| `message` | 判定消息 |
| 数值质量指标 | 空值率、异常值等 |

### 3.3 记录编号校验规则

参考 [`DiagnosisCaseService.recordIds()`](backend-java/src/main/java/com/hospital/wikiagent/agent/diagnosis/DiagnosisCaseService.java:942-958)：

## 7. 会话引用（diagnosis_case 标记）

排查任务与会话之间通过 `{{diagnosis_case:DCASE_xxx}}` 标记关联。

### 7.1 写入

[`AgentConversationMemory.appendDiagnosisCaseReference()`](backend-java/src/main/java/com/hospital/wikiagent/agent/memory/AgentConversationMemory.java:255-271)：

1. 写入一条 user 消息：`"开始异常排查：{ruleName}；{symptom}"`
2. 写入一条 assistant 消息：`"{{diagnosis_case:DCASE_xxx}}"`，digest 为 `"异常排查任务已创建"`

### 7.2 读取

会话恢复时（[`AgentChatView.restoreSession`](frontend-vue/src/views/AgentChatView.vue:79) → [`store.restoreSession`](frontend-vue/src/stores/agent.ts:660-702)）：

1. 从历史消息中提取 `{{diagnosis_case:DCASE_xxx}}` 正则匹配
2. 存入 `chatMessage.diagnosisCaseId`
3. `AgentChatView.restoreDiagnosisCases()` 合并 localStorage 和消息引用的 caseId 列表
4. 逐一调用 `GET /api/diagnosis/cases/{caseId}` 懒加载快照

### 7.3 localStorage 备份

[`AgentChatView.rememberDiagnosisCase()`](frontend-vue/src/views/AgentChatView.vue:152-156)：

- Key: `diagnosisCases:{sessionId}`
- Value: `["DCASE_xxx", "DCASE_yyy"]` JSON 数组
- 作为会话消息引用的补充，防止消息被截断后丢失 caseId

## 8. 自动取证数据流

[`DiagnosisCaseEvidenceService.collect()`](backend-java/src/main/java/com/hospital/wikiagent/agent/diagnosis/DiagnosisCaseEvidenceService.java:60-116) 按三个阶段收集证据：

```
           recordField + recordIds
                  │
     ┌────────────┼────────────┐
     ▼            ▼            ▼
┌─────────┐  ┌─────────┐  ┌─────────┐
│ Stage 1  │  │ Stage 2  │  │ Stage 3  │
│ 业务源表  │  │ 真实库   │  │ 最终概览  │
│          │  │ 中间表   │  │ 统计     │
└────┬────┘  └────┬────┘  └────┬────┘
     │            │            │
     ▼            ▼            ▼
  查到 /      查到 /       查到 /
  未查到      未查到        未查到
```

每个阶段返回：
- `status`: `COMPLETED` | `NEEDS_MANUAL_EVIDENCE`
- `rowCount`: 返回行数
- `rows`: 最多 50 行预览
- `meaning`: 该阶段证据的业务含义

最终 `display` 汇总：
```json
{
  "found": ["业务记录与事件抽取结果：查到1条记录"],
  "notFound": ["真实库指标中间表：没有查到该记录"],
  "unfinished": [],
  "conclusion": "数据链路中有环节没有找到这条记录...",
  "nextAction": "确认记录号和统计窗口后，重点检查没有查到记录的环节。"
}
```
