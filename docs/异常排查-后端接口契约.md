## 2. 创建排查任务

### 2.1 请求

```
POST /api/diagnosis/cases
Content-Type: application/json
Authorization: Bearer {token}
```

**请求体 (`CreateRequest`)**：

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|------|------|------|----------|------|
| `sessionId` | `string` | ✅ | `@NotBlank`, `@Size(max=128)` | 当前会话 ID |
| `ruleId` | `string` | ✅ | `@Pattern(regexp="^HXZD-\\d{3}-\\d{3}$")` | 指标编码，如 `HXZD-003-004` |
| `profileId` | `string` | ✅ | `@Pattern(regexp="^HXZD-\\d{3}-\\d{3}(?:_\\d{3})?$")` | 口径变体 ID |
| `statStart` | `string` | ✅ | `@NotBlank`, `@Size(max=40)` | 统计开始时间，ISO 格式 |
| `statEnd` | `string` | ✅ | `@NotBlank`, `@Size(max=40)` | 统计结束时间，ISO 格式 |
| `modelId` | `string` | ✅ | `@NotBlank`, `@Size(max=64)` | 模型 ID |
| `caseInput` | `object` | ❌ | - | 案例输入（创建时为空对象） |
| `expectedClassification` | `object` | ❌ | - | 预期分类（创建时为空对象） |

参考：[`DiagnosisCaseController.java:92-101`](backend-java/src/main/java/com/hospital/wikiagent/api/DiagnosisCaseController.java:92)

### 2.2 后端处理流程

[`DiagnosisCaseService.create()`](backend-java/src/main/java/com/hospital/wikiagent/agent/diagnosis/DiagnosisCaseService.java:93-128)：

1. **校验时间范围**：`statStart` 必须早于 `statEnd`，否则报 `DIAGNOSIS_PERIOD_INVALID`
2. **读取生效口径**：`RuleReadRepository.effectiveRule(ruleId, hospitalId, profileId)`
3. **丰富口径数据**：`dataFlowSqlExporter.enrichRule()` 补充可执行 SQL 链路
4. **查找实体页**：`EntityPageParser.getEntity(profileId, hospitalId)`，未找到报 `DIAGNOSIS_PROFILE_NOT_FOUND`
5. **冻结口径快照**：提取 `ruleId, ruleName, profileId, profileName, effectiveLevel, definition, formula, numeratorRule, denominatorRule, caliber, dataSource, standardSql, sourceExtractSql, dataFlow, knowledgeReleaseId, timeRange`
6. **生成 caseId**：`DCASE_` + 20 位随机 UUID 子串
7. **写入会话引用**：`AgentConversationMemory.appendDiagnosisCaseReference()` 插入 `{{diagnosis_case:DCASE_xxx}}` 标记

## 3. 读取任务快照

### 3.1 请求

```
GET /api/diagnosis/cases/{caseId}
Authorization: Bearer {token}
```

- `caseId` 格式：`@Pattern(regexp="^DCASE_[A-Za-z0-9_]+$")`

### 3.2 后端处理

[`DiagnosisCaseService.load()`](backend-java/src/main/java/com/hospital/wikiagent/agent/diagnosis/DiagnosisCaseService.java:130-134)：

1. 从 `DiagnosisCaseStore` 加载快照
2. 校验 `hospitalId` + `userId`，不匹配报 `DIAGNOSIS_CASE_NOT_FOUND` (404)
3. 调用 `withExecutableDataFlow()` 重新丰富口径的执行 SQL（数据链路可能在后续发生变化，这里实时渲染）
4. 模型 ID 自动降级：`aliyun-qwen-plus` → `aliyun-qwen-distill-7b`

### 3.3 使用场景

- 会话恢复时前端懒加载排查任务状态
- 每次 action 调用后，前端也可以用返回的快照原地替换

## 4. 提交统一动作

### 4.1 请求

```
POST /api/diagnosis/cases/{caseId}/actions
Content-Type: application/json
```

**请求体 (`ActionRequest`)**：

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|------|------|------|----------|------|
| `action` | `string` | ✅ | 必须在允许的枚举列表中（见下文） | 动作名称 |
| `payload` | `object` | ✅ | - | 动作参数 |

参考：[`DiagnosisCaseController.java:103-108`](backend-java/src/main/java/com/hospital/wikiagent/api/DiagnosisCaseController.java:103)

### 4.2 允许的动作列表

[`DiagnosisCaseController.java:105-106`](backend-java/src/main/java/com/hospital/wikiagent/api/DiagnosisCaseController.java:105)

```regexp
^(CONFIRM_CALIBER|RUN_BASE_CHECKS|RUN_GATE|RECHECK_GATE|SUBMIT_CASE|
  CONFIRM_CASE_CALIBER|SUBMIT_EVIDENCE|CONFIRM_CAUSE|CLOSE_AS_CORRECT|
  BUILD_CANDIDATE|RUN_SHADOW_TRIAL|SAVE_HOSPITAL_DRAFT|REVALIDATE_HOSPITAL_DRAFT)$
```

### 4.3 动作详解

[`DiagnosisCaseService.action()`](backend-java/src/main/java/com/hospital/wikiagent/agent/diagnosis/DiagnosisCaseService.java:161-195)

#### 4.3.1 CONFIRM_CALIBER — 确认当前口径

- **前置步骤**：必须是 `CALIBER_CONFIRMATION`
- **载荷**：`{ "confirmed": true }`
- **结果**：
  - 成功 → `status=IN_PROGRESS`, `currentStep=GATE_1_SCHEMA`, `gateResults=[]`
  - 失败 → `CALIBER_NOT_CONFIRMED`

#### 4.3.2 RUN_BASE_CHECKS — 重新执行基础检查

- **前置步骤**：必须是 `BASE_CHECKS_RESULT` 或以 `GATE_` 开头
- **载荷**：无
- **结果**：
  - 如果当前在 `BASE_CHECKS_RESULT` → 直接重跑
  - 如果在 Gate N → 调用 `runGate(N)` 重新执行
- **与 RECHECK_GATE 的关系**：前端 `retryCurrentGate` 调用 `RECHECK_GATE`，后端内部按情况分发

#### 4.3.3 RUN_GATE — 执行指定关卡

- **前置步骤**：必须是对应 Gate 的步骤
  - `{ "gate": 1 }` → 必须在 `GATE_1_SCHEMA`
  - `{ "gate": 2 }` → 必须在 `GATE_2_EVENT`
  - `{ "gate": 3 }` → 必须在 `GATE_3_VALUE`
  - gate 不在 [1,3] → `DIAGNOSIS_GATE_INVALID`

**Gate 1: 数据结构校验** ([`DiagnosisCaseService.java:347-369`](backend-java/src/main/java/com/hospital/wikiagent/agent/diagnosis/DiagnosisCaseService.java:347))

- 调用 `BatchDataInitializationValidator.validate()`
- 检查：表是否存在、字段是否缺失、血缘是否可解析
- 返回值：
  - `PASSED` — `decision == RUNNABLE || decision == NO_SAMPLE`
  - `BLOCKED` — 包含 `errorCode` + `repairSuggestion`
- 修复建议见 [`schemaRepairSuggestion()`](backend-java/src/main/java/com/hospital/wikiagent/agent/diagnosis/DiagnosisCaseService.java:371-382)

**Gate 2: 事件与抽取校验** ([`DiagnosisEventGateService`](backend-java/src/main/java/com/hospital/wikiagent/agent/diagnosis/DiagnosisEventGateService.java))

- 执行抽取 SQL + 概览 SQL
- 返回 `executionEvidence`（numeratorCount, denominatorCount, resultValue, overviewSqlHash 等）

**Gate 3: 数据可用性校验** ([`DiagnosisValueGateService`](backend-java/src/main/java/com/hospital/wikiagent/agent/diagnosis/DiagnosisValueGateService.java))

- 检查样本量、数值质量
- Gate 3 通过且当前案例已填写 → 进入 `CASE_INVESTIGATION`
- Gate 3 通过但案例未填写 → 进入 `CASE_INPUT`

#### 4.3.4 RECHECK_GATE — 修复后重新检查当前步骤

- 效果同 `RUN_GATE`，但从 DiagnosisCasePanel 的 `retryCurrentGate` 方法发起
- `AgentChatView` 中的 `diagnosisAction` 对 `RECHECK_GATE` 同样执行 `advanceDiagnosisGates`

#### 4.3.5 SUBMIT_CASE — 提交案例

- **前置步骤**：必须是 `CASE_INPUT`
- **载荷**：
  ```json
  {
    "recordField": "ENCOUNTER_ID",
    "recordId": "484625508177383425",
    "recordIds": ["484625508177383425"],
    "symptom": "该患者存在已作废...",
    "expectedResult": "",
    "businessUniqueKey": "ENCOUNTER_ID",
    "expectedClassification": { "status": "WAITING_CONFIRMATION" }
  }
  ```
- **校验**：
  - `recordField` 必须非空
  - `recordIds` 至少有一个（最多 20 个）
  - 记录编号格式：`[A-Za-z0-9_.:-]{1,100}`
- **结果**：
  - success → `status=WAITING_CASE_CALIBER_CONFIRMATION`, `currentStep=CASE_CALIBER_CLARIFICATION`
  - 同时生成 `caseExpectedClassification`（包含 denominatorRule, numeratorRule, numeratorCount, denominatorCount, decisionOrder, nextEvidenceTemplate 等）

#### 4.3.6 CONFIRM_CASE_CALIBER — 确认案例口径

- **前置步骤**：必须是 `CASE_CALIBER_CLARIFICATION`
- **载荷**：`{ "confirmed": true }`
- **结果**：
  - success → `status=IN_PROGRESS`, `currentStep=CASE_INVESTIGATION`
  - 自动推断 `hospitalExpectedMembership`（DENOMINATOR_ONLY / EXCLUDED / NUMERATOR / UNKNOWN）

#### 4.3.7 SUBMIT_EVIDENCE — 提交排查证据

- **前置步骤**：必须是 `CASE_INVESTIGATION`
- **载荷**：
  ```json
  {
    "type": "IMPLEMENTER_SQL_REQUIREMENT",
    "suspectedLayer": "SOURCE_EXTRACT",
    "summary": "...",
    "requirement": "排除会诊状态为...",
    "treatment": "EXCLUDE",
    "patchConditions": [
      { "treatment": "EXCLUDE", "field": "A.CONSULT_STATUS_CODE", "operator": "EQ", "value": "399329839" }
    ],
    "expectedCaseEffect": "候选抽取后不再包含上述案例编号",
    "validationSql": "...",
    "candidateSql": "...",
    "requestAiAnalysis": false,
    "runAutomatic": true
  }
  ```
- **如果 `runAutomatic=true`**：调用 `DiagnosisCaseEvidenceService.collect()` 沿数据链路自动取证
- **如果 `type=IMPLEMENTER_SQL_REQUIREMENT`**：
  - 分析要求（`requirementAnalysis`）
  - 提供当前 SQL 上下文（`sqlContext`）
  - 自动调用 `automaticallyBuildAndTrial()` 构建候选 SQL 并影子试跑
- **如果 `requestAiAnalysis=true`**：调用模型解释证据（限制 220 中文字符）

自动取证（[`DiagnosisCaseEvidenceService.collect()`](backend-java/src/main/java/com/hospital/wikiagent/agent/diagnosis/DiagnosisCaseEvidenceService.java:60-116)）按三个阶段执行：

| 阶段 | 数据库角色 | 说明 |
|------|-----------|------|
| 业务记录与事件抽取结果 | `BUSINESS` | 在业务源表中按记录编号查询 |
| 真实库指标中间表 | `REAL` | 在真实库中间表中按记录编号查询 |
| 最终指标结果 | `REAL` | 执行概览 SQL 确认最终判定 |

每个阶段如查询失败则标记 `NEEDS_MANUAL_EVIDENCE`，不阻塞后续阶段。

#### 4.3.8 CONFIRM_CAUSE — 确认原因

- **前置步骤**：必须是 `CASE_INVESTIGATION`
- **载荷**：`{ "conclusion": "..." }`
- **条件**：`evidence` 非空
- **结果**：`status=CAUSE_CONFIRMED`, `currentStep=CHANGE_PROPOSAL`

#### 4.3.9 CLOSE_AS_CORRECT — 确认计算正确并关闭

- **前置步骤**：必须是 `CASE_INVESTIGATION`
- **载荷**：`{ "conclusion": "..." }`
- **条件**：`evidence` 非空
- **结果**：`status=COMPLETED`, `currentStep=COMPLETED`, `outcome=CALCULATION_CONFIRMED_CORRECT`

#### 4.3.10 BUILD_CANDIDATE — 构建候选方案

- **前置步骤**：必须是 `CHANGE_PROPOSAL`
- **载荷**：
  ```json
  {
    "type": "SQL_CHANGE",
    "layer": "SOURCE_EXTRACT",
    "requirements": "...",
    "sql": "...",
    "expectedCaseEffect": "..."
  }
  ```
- **校验**：
  - `type` 必须是 `DATA_REPAIR | EVENT_CONFIG | SQL_CHANGE | CALIBER_CHANGE`
  - `layer` 必须是 `SOURCE_EXTRACT | OVERVIEW`
  - 候选 SQL 必须通过只读校验（`ReadOnlySqlValidator`）
  - 候选 SQL 不能引用原口径之外的表
  - 候选 SQL 必须保留原口径模板参数
- **SQL 生成优先级**：
  1. 载荷中提供的 `sql`（实施人员提供）
  2. 程序按 `patchConditions` 结构化生成（`SafeSqlPredicatePatcher`）
  3. 程序按已知约定确定性生成（`deterministicCandidate`）— 仅处理会诊作废、完成时间、首条医嘱

#### 4.3.11 RUN_SHADOW_TRIAL — 影子试跑

- **前置步骤**：必须是 `SHADOW_TRIAL`
- **载荷**：无
- **结果**：
  - `passed=true` → `SHADOW_PASSED`, `DRAFT_SAVE`
  - `passed=false` → `SHADOW_FAILED`, 停留在 `SHADOW_TRIAL`
  - 环境不支持 → `SHADOW_RUNNER_UNAVAILABLE`

#### 4.3.12 SAVE_HOSPITAL_DRAFT — 保存医院草稿

- **前置步骤**：必须是 `DRAFT_SAVE`
- **载荷**：`{ "confirmed": true }`
- **权限**：需要 `indicator_diagnosis_release` 权限
- **结果**：`status=DRAFT_SAVED`, `currentStep=COMPLETED`

#### 4.3.13 REVALIDATE_HOSPITAL_DRAFT — 重新验证草稿

- **前置步骤**：必须是 `COMPLETED`
- **载荷**：无
- **结果**：
  - 基线过期 → `DRAFT_BASELINE_EXPIRED`
  - 重新试跑通过 → `DRAFT_REVALIDATED`
  - 重新试跑失败 → `DRAFT_REVALIDATION_FAILED`

### 5.2 后端处理

[`DiagnosisCaseEvidenceService.details()`](backend-java/src/main/java/com/hospital/wikiagent/agent/diagnosis/DiagnosisCaseEvidenceService.java:122-213)：

1. 从 Gate 2 获取冻结的计算结果（`numeratorCount`, `denominatorCount`, `overviewSqlHash`）
2. 校验 `overviewSqlHash` 一致（防止知识库已变化）
3. 从明细提取器获取明细 SQL
4. 首次查询执行同源明细并做分子/分母双计数对账
5. 缓存 30 分钟

## 7. DiagnosisCaseSnapshot 完整结构

[`DiagnosisCaseSnapshot.java`](backend-java/src/main/java/com/hospital/wikiagent/agent/diagnosis/DiagnosisCaseSnapshot.java)

```java
public record DiagnosisCaseSnapshot(
    String caseId,                              // DCASE_ + 20位随机
    String hospitalId,                          // 医院隔离
    String userId,                              // 用户隔离
    String sessionId,                           // 所属会话
    String status,                              // 主状态（见下文状态机）
    String currentStep,                         // 当前步骤
    String ruleId,                              // 指标编码
    String profileId,                           // 口径变体
    String knowledgeReleaseId,                  // 知识库版本
    String modelId,                             // 模型ID（加载时自动降级）
    Map<String, Object> caseInput,             // 案例输入
    Map<String, Object> caliberSnapshot,       // 冻结口径快照
    Map<String, Object> caseExpectedClassification, // 案例口径澄清
    List<Map<String, Object>> gateResults,     // 三门校验结果
    List<Map<String, Object>> evidence,        // 证据列表
    Map<String, Object> causeConclusion,       // 原因结论
    Map<String, Object> changeProposal,        // 修改方案
    Map<String, Object> candidateSql,          // 候选SQL
```
