## 1. 功能概述

异常排查功能是一套对话式指标异常排查工具链，面向实施人员，用于按"冻结口径 → 三门基础校验 → 案例查因 → 候选 SQL + 影子试跑 → 医院草稿保存"的顺序状态机推进。

### 1.1 核心设计原则

- **真实库负责正式计算**，双库验证只在异常排查时启动
- **程序负责生成可复核事实**，模型负责解释事实和指导下一步
- **无法由证据证明的内容**，必须明确标记为假设
- 不改变当前指标卡片的正式结果
- 只有实施人员主动点击"进入异常排查"，才启动深入诊断

## 3. 核心数据流

```
用户点击"开始异常排查"
  │
  ├─► [前端] GuidedTaskPanel 构建 CreateDiagnosisCaseInput
  │     ├─ ruleId（单选指标）
  │     ├─ profileId（口径变体）
  │     ├─ statStart / statEnd（时间范围）
  │     └─ modelId、sessionId、caseInput
  │
  ├─► [API] POST /api/diagnosis/cases
  │     └─► DiagnosisCaseService.create()
  │           ├─ 读取当前生效口径（RuleReadRepository）
  │           ├─ 冻结口径快照（caliberSnapshot）
  │           ├─ 创建 DCASE_xxx 任务
  │           ├─ 写入会话引用（AgentConversationMemory）
  │           └─ 返回 DiagnosisCaseSnapshot (status=CALIBER_CONFIRMATION)
  │
  ├─► [前端] DiagnosisCasePanel 渲染口径确认卡片
  │
  ├─► [用户] 点击"异常排查基础校验"
  │
  ├─► [API] POST /api/diagnosis/cases/{caseId}/actions
  │     ├─ CONFIRM_CALIBER → 进入 GATE_1_SCHEMA
  │     ├─ RUN_GATE(1): 数据结构校验（表/字段/血缘）
  │     ├─ RUN_GATE(2): 事件与抽取校验（执行抽取 SQL + 概览 SQL）
  │     └─ RUN_GATE(3): 数据可用性校验（数值、样本量）
  │
  ├─► [用户] 填写案例记录编号
  │
  ├─► [API] SUBMIT_CASE → CASE_CALIBER_CLARIFICATION
  │     └─► CONFIRM_CASE_CALIBER → CASE_INVESTIGATION
  │
  ├─► [用户] 填写排查要求（业务规则 + 判断条件 + 可选 SQL）
  │
  ├─► [API] SUBMIT_EVIDENCE
  │     ├─ 自动取证（可选）：沿数据链路查询业务源/中间表/概览
  │     └─ 自动构建候选 SQL + 影子试跑（可选）
  │
  ├─► [API] BUILD_CANDIDATE → SHADOW_TRIAL
  │     └─► RUN_SHADOW_TRIAL（双库影子执行器校验）
  │
  └─► [API] SAVE_HOSPITAL_DRAFT → COMPLETED
        └─ 保存医院草稿版本，不影响正式指标计算
```

## 4. 关键约束

| 约束项 | 说明 |
|--------|------|
| **指标单选** | 异常排查每次只排查一个指标（[`GuidedTaskPanel.vue:85-87`](frontend-vue/src/components/GuidedTaskPanel.vue:85)） |
| **案例记录上限** | 一次最多 20 个同类记录编号（[`DiagnosisCaseService.java:949-951`](backend-java/src/main/java/com/hospital/wikiagent/agent/diagnosis/DiagnosisCaseService.java:949)） |
| **候选 SQL 安全** | 不能新增表、JOIN、子查询，只能修改已有字段的过滤条件（[`DiagnosisCaseService.java:1031-1045`](backend-java/src/main/java/com/hospital/wikiagent/agent/diagnosis/DiagnosisCaseService.java:1031)） |
| **模型不写 SQL** | 模型只解释证据，不负责重写复杂 SQL，不能绕过程序校验 |
| **会话引用** | 排查引用写入 `{{diagnosis_case:DCASE_xxx}}`，会话恢复时前端懒加载 |
| **医院隔离** | 读取始终校验 hospitalId + userId，禁止跨院串读 |
| **影子试跑** | 候选 SQL 在影子环境中执行，不覆盖正式中间表 |
