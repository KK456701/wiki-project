## 二、已覆盖口径

### 2.1 HXZD-008 系列

- `HXZD-008-001`
- `HXZD-008-002_001`
- `HXZD-008-002_002`
- `HXZD-008-003`
- `HXZD-008-004`

这 5 个口径共用同类 `OperationRecord` 拓展事件逻辑。Oracle 版本已完成以下改写：

- `GETDATE()` 改为 `SYSDATE`。
- `DATEDIFF` 改为 Oracle 日期差计算。
- `TOP 1` 改为 `FETCH FIRST 1 ROW ONLY`。
- `STUFF + FOR XML PATH` 改为 `LISTAGG`。
- `LEFT` 改为 `SUBSTR`。
- 原脚本中无法执行的空别名表达式改为有明确类型的 `NULL`。

特别说明：HXZD-008 的指标主源表 SQL 读取真实库 `MRAS_PATIENT_EVENT`，仍应使用 SQL Server 方言；Oracle 化的是生成患者事件的业务库拓展事件 SQL。运行页面同时出现 SQL Server 主源表和 Oracle 拓展事件是符合数据链路设计的，不是方言选择错误。

### 2.2 HXZD-011 系列

- `HXZD-011-001`
- `HXZD-011-002`

两个口径复用同一类手术重合抽取 SQL。Oracle 版本已完成：

- 字符串聚合改为 `LISTAGG`。
- 保留手术名称与科室名称两个不同输出字段，修复候选 SQL 中重复别名导致字段被覆盖的问题。
- 相关子查询、人员匹配和重合手术列表保持原口径语义。

### 2.3 HXZD-012 系列

- `HXZD-012-001_001`
- `HXZD-012-001_002`
- `HXZD-012-002_001`
- `HXZD-012-002_002`
- `HXZD-012-003_001`
- `HXZD-012-003_002`
- `HXZD-012-004_001`
- `HXZD-012-004_002`

本组按实际复用关系维护 4 段 Oracle 源表 SQL，并为需要并发症事件的口径增加 1 段 Oracle `MahpComplication` SQL。主要修正：

- SQL Server 内联值表、字符串拼接和字符串聚合改为 Oracle 写法。
- `TOP 1`、日期差、空值函数和截断函数改为 Oracle 写法。
- 保留各方案不同的统计字段和业务条件，没有把 4 组源表 SQL错误合并为同一份。

## 三、运行时方言选择

知识库实体现在同时保存：

- 原 SQL Server 业务源 SQL。
- 对应的 Oracle 业务源覆写 SQL。

程序根据当前启用的业务库连接自动选择：

- 业务库为 Oracle：选择 `源表-oracle` 和 `oracle关联拓展事件`。
- 业务库为 SQL Server：继续使用原 `源表` 和原关联拓展事件。
- 单元测试或未注入 Spring 数据源的默认行为：按当前项目默认业务库 **Oracle** 处理。

正式计算、初始化校验、抽取请求契约校验、口径接口和数据链路页面共用同一个方言选择器，避免页面显示 Oracle SQL、正式抽取却仍执行 SQL Server SQL。

当前运行设置已经核实：业务库引擎为 Oracle，真实库为 SQL Server。服务重启后，运行接口返回：

- HXZD-011/012 的 `sourceExtractSql` 为 Oracle 版。
- HXZD-008 的 `OperationRecord` 拓展事件节点为 Oracle 版。
- HXZD-008 的主源表节点仍按真实库 SQL Server 运行。
