## 二、HXZD-002-002 分子为 0 是否正常

不能简单认定为业务正常，但它确实是当前 SQL 和当前源数据算出的结果，不是前端丢数：

- 真实库抽取行数：3915。
- 分母：3915。
- 分子：0。
- 3915 行的 `SUPERIOR_ROUND_STANDARD` 均为未命中值 `98176`。
- 源表规则要求 8 个固定病历监控 ID 的“应完成数”等于“按时完成数”。
- `INPATIENT_EMR_INCOMPLETE` 中绝大多数记录处于未完成状态；全库只有 12 条完成状态记录，满足当前完成时间条件的只有 5 条，而本统计窗口内没有患者满足完整分子规则。

因此应分成两层判断：

1. **程序计算事实正确**：按当前 SQL，分子就是 0。
2. **业务结果需要核实**：需要确认本院病历完成状态、提醒时间和 8 个监控 ID 是否仍与公版一致；如果现场使用了其他监控 ID 或完成状态语义，当前公版会把真实完成病例全部判为未完成。

另外发现目标值配置冲突：

- 知识库写明“逐步提高”，目标值为 0.95。
- 运行库 `MRAS_TARGET_DEFINITION` 本次返回目标值 `0.0000`。
- 因而页面会按 `0 >= 0` 显示达标。

已修正知识库 SQL 中原先把“小于目标”写成达标的比较方向，但没有擅自修改医院运行库目标值。医院应把该指标实际目标值确认后写入运行配置；在此之前，“达标”结论不具备业务可信度。

## 四、其余 24 个无样本如何理解

“无样本”是当前生效口径执行后分母为 0，不等于数据库连不上，也不等于 SQL 执行失败。本次可分三类：

### 1. 当前抽取 SQL 返回 0 行

- HXZD-005-001。
- HXZD-006-001、HXZD-006-002、HXZD-006-003_001。
- HXZD-007-001。
- HXZD-008 全部 5 个口径。
- HXZD-009 可执行的 5 个口径。
- HXZD-015 两个口径。

日志显示这些源查询均执行成功，但没有向对应目标表插入记录。这证明“当前口径筛选结果为 0”，但实施时仍应确认现场事件、病历模板 ID、值域码和业务状态是否与公版一致。

### 2. 有上游数据，但最终口径分母为 0

- HXZD-012-003 两个口径。
- HXZD-012-004 两个口径。

事件链已同步 4178 行，公版手术分级中间结果曾写入 11 行，但没有记录满足这四个口径各自的四级手术、多学科讨论或三四级实际开展分母条件。因此不能说“业务库完全没数据”，准确说法是“有上游手术数据，但当前指标条件下无样本”。

### 3. 真实库既有表直接统计后分母为 0

- HXZD-010-001。
- HXZD-013-001。
- HXZD-016-002。

这三项不要求业务库抽取中间表；本次直接执行真实库统计 SQL，分母为 0。
