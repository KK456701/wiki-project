| `startDiagnosis` | `input: CreateDiagnosisCaseInput` | 触发"异常排查"流程 |

### 2.3 用户操作流程

**第一步：选择排查模式**

用户点击"开始异常排查"按钮（[`GuidedTaskPanel.vue:169-171`](frontend-vue/src/components/GuidedTaskPanel.vue:169)），`task` 设为 `'diagnose'`。

与"算指标"的关键区别：
- 指标只能**单选**（[`GuidedTaskPanel.vue:85-87`](frontend-vue/src/components/GuidedTaskPanel.vue:85)）：点击新指标会替换旧选择
- 不显示"全选"按钮
- 提示文字为"一次只排查一个指标"

**第二步：选择指标**

- 组件挂载时通过 `GET /api/kb/rules/list` 加载全部活跃指标（[`GuidedTaskPanel.vue:56-65`](frontend-vue/src/components/GuidedTaskPanel.vue:56)）
- 支持搜索过滤（[`GuidedTaskPanel.vue:36-41`](frontend-vue/src/components/GuidedTaskPanel.vue:36)）
- `selected` 数组在 diagnose 模式下始终最多一个元素

**第三步：选择时间范围**

- 预设选项：本月、上月、近三个月、近半年、今年以来、去年全年、自定义月份区间
- 时间选择器定义：[`GuidedTaskPanel.vue:27-34`](frontend-vue/src/components/GuidedTaskPanel.vue:27)

**提交按钮**

- `canSubmit` 条件（[`GuidedTaskPanel.vue:51-54`](frontend-vue/src/components/GuidedTaskPanel.vue:51)）：
  - 非 disabled
  - 至少已选一个指标
  - 时间文本非空
- 提交时调用 `diagnosisPeriod()` 将时间转为 ISO 格式（`YYYY-MM-DDTHH:00:00`）

## 3. AgentChatView：创建排查任务

### 3.1 接收 startDiagnosis 事件

[`AgentChatView.vue:167-182`](frontend-vue/src/components/GuidedTaskPanel.vue:167)

```typescript
async function startDiagnosis(input: CreateDiagnosisCaseInput) {
  diagnosisBusy.value = 'creating'  // 全局忙碌状态
  store.error = ''
  try {
    const created = await createDiagnosisCase(store.token, input)
    guidedOpen.value = false         // 关闭引导面板
    diagnosisCases.value.push(created)  // 追加到排查任务列表
    rememberDiagnosisCase(store.sessionId, created.caseId)
    // 滚动到底部
    await nextTick()
    conversation.value?.scrollTo({ top: conversation.value.scrollHeight, behavior: 'smooth' })
  } catch (error) {
    store.error = error instanceof Error ? error.message : '异常排查任务创建失败。'
  } finally {
    diagnosisBusy.value = ''
  }
}
```

### 3.2 创建请求

调用 [`createDiagnosisCase`](frontend-vue/src/api/agent.ts:322-332)：

```
POST /api/diagnosis/cases
Content-Type: application/json
Authorization: Bearer {token}

{
  "sessionId": "...",
  "ruleId": "HXZD-003-004",
  "profileId": "HXZD-003-004",
  "statStart": "2025-01-01T00:00:00",
  "statEnd": "2025-06-01T00:00:00",
  "modelId": "...",
  "caseInput": {},
  "expectedClassification": {}
}
```

返回 `DiagnosisCaseSnapshot`，核心字段：
- `caseId`: `"DCASE_xxxxxxxxxxxxxxxxxxxx"`（20 位随机字符）
- `status`: `"WAITING_CALIBER_CONFIRMATION"`
- `currentStep`: `"CALIBER_CONFIRMATION"`
- `caliberSnapshot`: 冻结的口径快照（含 ruleName, profileName, definition, formula, dataFlow 等）

### 3.3 任务持久化

- 前端通过 `localStorage` 按 sessionId 记住 caseId 列表（[`AgentChatView.vue:148-156`](frontend-vue/src/views/AgentChatView.vue:148)）
- 后端通过 `AgentConversationMemory.appendDiagnosisCaseReference()` 在会话消息中写入 `{{diagnosis_case:DCASE_xxx}}` 引用（[`AgentConversationMemory.java:255-271`](backend-java/src/main/java/com/hospital/wikiagent/agent/memory/AgentConversationMemory.java:255)）

## 4. DiagnosisCasePanel：排查面板交互

### 4.1 组件渲染

每个 `DiagnosisCaseSnapshot` 渲染一个 [`DiagnosisCasePanel`](frontend-vue/src/components/DiagnosisCasePanel.vue) 实例（[`AgentChatView.vue:451-458`](frontend-vue/src/views/AgentChatView.vue:451)）：

```html
<DiagnosisCasePanel
  v-for="item in diagnosisCases"
  :key="item.caseId"
  :snapshot="item"
  :token="store.token"
  :busy="diagnosisBusy === item.caseId"
  @action="(action, payload) => diagnosisAction(item, action, payload)"
/>
```

### 4.2 动作分发

`diagnosisAction` 函数（[`AgentChatView.vue:184-202`](frontend-vue/src/views/AgentChatView.vue:184)）：

```typescript
async function diagnosisAction(snapshot, action, payload) {
  diagnosisBusy.value = snapshot.caseId
  store.error = ''
  try {
    let updated = await actOnDiagnosisCase(store.token, snapshot.caseId, action, payload)
    replaceDiagnosisSnapshot(updated)  // 原地替换列表中的快照
    // 口径确认或重新检查后，自动推进全部通过的门
    if (action === 'CONFIRM_CALIBER' || action === 'RECHECK_GATE' || action === 'RUN_BASE_CHECKS') {
      updated = await advanceDiagnosisGates(updated)
    }
  } catch (error) {
    store.error = error instanceof Error ? error.message : '异常排查步骤执行失败。'
  } finally {
    diagnosisBusy.value = ''
  }
}
```

### 4.3 自动推进逻辑

`advanceDiagnosisGates`（[`AgentChatView.vue:216-229`](frontend-vue/src/views/AgentChatView.vue:216)）：

```typescript
async function advanceDiagnosisGates(initial) {
  let current = initial
  for (;;) {
    const gate = currentGateNumber(current.currentStep)  // 1, 2, 3 或 0
    if (!gate) return current
    // 如果该关已有 BLOCKED 结果，停止推进
    const existing = current.gateResults.find(item => Number(item.gate) === gate)
    if (String(existing?.status || '') === 'BLOCKED') return current
    // 执行 RUN_GATE，原地替换快照
    current = await actOnDiagnosisCase(store.token, current.caseId, 'RUN_GATE', { gate })
    replaceDiagnosisSnapshot(current)
    const result = current.gateResults.find(item => Number(item.gate) === gate)
    if (String(result?.status || '') === 'BLOCKED') return current
  }
}
```

关键行为：前端连续调用 RUN_GATE(1) → RUN_GATE(2) → RUN_GATE(3)，直到遇到第一个 BLOCKED 或全部通过。

## 6. 排查要求提交流程

用户在排查要求表单中填写并提交（[`DiagnosisCasePanel.vue:234-283`](frontend-vue/src/components/DiagnosisCasePanel.vue:234)）：

### 6.1 表单字段

| 字段 | 说明 |
|------|------|
| `investigationLayer` | `SOURCE_EXTRACT`（抽取SQL）或 `OVERVIEW`（统计SQL） |
| `investigationTreatment` | `EXCLUDE`（排除）或 `INCLUDE`（纳入） |
| `investigationRequirement` | 业务规则描述文本 |
| `investigationConditions[]` | 结构化判断条件数组：`{field, operator, value}` |
| `investigationSql` | 可选，验证 SQL |
| `investigationCandidateSql` | 可选，完整候选 SQL |

### 6.2 提交载荷

```
POST /api/diagnosis/cases/{caseId}/actions
{
  "action": "SUBMIT_EVIDENCE",
  "payload": {
    "type": "IMPLEMENTER_SQL_REQUIREMENT",
    "suspectedLayer": "SOURCE_EXTRACT",
    "summary": "...",
    "requirement": "...",
    "treatment": "EXCLUDE",
    "patchConditions": [{ "treatment": "EXCLUDE", "field": "A.CONSULT_STATUS_CODE", "operator": "EQ", "value": "399329839" }],
    "expectedCaseEffect": "候选抽取后不再包含上述案例编号",
    "validationSql": "...",
    "candidateSql": "",
    "requestAiAnalysis": false
  }
}
```

### 6.3 提交后行为

1. 前端立即渲染一条"实施人员 · 排查要求"用户消息（[`DiagnosisCasePanel.vue:256-261`](frontend-vue/src/components/DiagnosisCasePanel.vue:256)）
2. 同时渲染一条"系统 · 正在生成候选 SQL" 临时消息（[`DiagnosisCasePanel.vue:474-476`](frontend-vue/src/components/DiagnosisCasePanel.vue:474)）
3. 后端自动尝试构建候选 SQL 并执行影子试跑
4. 请求返回后，`replaceDiagnosisSnapshot` 替换整个快照，卡片自动刷新

### 6.4 候选 SQL 构建规则

[`DiagnosisCasePanel` 的 `investigationTemplateIncomplete`](frontend-vue/src/components/DiagnosisCasePanel.vue:99-108) 控制前端校验：
- 必须填写业务规则
- 如果不提供完整候选 SQL，则必须至少有一组完整的判断条件（字段 + 运算符 + 值）

## 7. 分子分母明细查询

基础校验通过后，用户可以在口径澄清卡片中查看分子/分母明细：

```
GET /api/diagnosis/cases/{caseId}/details?group=numerator&page=1&pageSize=50
GET /api/diagnosis/cases/{caseId}/details?group=denominator&page=1&pageSize=50
```

- 前端通过 [`fetchDiagnosisCaseDetails`](frontend-vue/src/api/agent.ts:359-376) 调用
- 组件内使用 `DetailRowsTable` 子组件渲染明细表格
- 首次查询会执行同源明细抽取并对账计数，后续翻页/切换分类复用缓存
- 缓存有效期 30 分钟

## 8. 会话恢复

切换回包含排查任务的会话时（[`AgentChatView.vue:79-84`](frontend-vue/src/views/AgentChatView.vue:79)）：

1. `restoreSession` 从消息中提取 `{{diagnosis_case:DCASE_xxx}}` 引用
2. `restoreDiagnosisCases` 合并 localStorage 和消息引用中的 caseId
3. 逐一调用 `GET /api/diagnosis/cases/{caseId}` 懒加载快照
4. `DiagnosisCasePanel` 根据快照的 `currentStep` 渲染对应阶段卡片
