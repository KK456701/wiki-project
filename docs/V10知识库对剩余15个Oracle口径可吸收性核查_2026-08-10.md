# V10 知识库对剩余 15 个 Oracle 口径可吸收性核查

## 一、结论

本次核查对象为公司 `test` 分支提交 `8a578ed`（`# zxb 更新知识V10`）中的：

```text
backend-java/src/main/resources/knowledge-index
```

目标运行知识库为：

```text
backend-java/src/main/resources/knowledge-index_backup_20260801_150233
```

结论：**V10 不能完整解决此前归类为“必须重写 Oracle SQL”的 15 个口径，当前不应把相关实体页或 Oracle SQL块吸收到运行知识库。**

本次没有修改目标运行知识库。主要原因如下：

1. 5 个 HXZD-008 口径共用的核心 `OperationRecord` Oracle事件 SQL仍不能在 Oracle执行。
2. 2 个 HXZD-011 口径共用的 Oracle源表 SQL存在重复输出别名，Oracle实测失败。
3. 8 个 HXZD-012 口径只补了部分公共事件和两组源表 SQL，另两组源表 SQL仍为空。
4. 当前 `EntityPageParser`只读取 `源表`和`关联拓展事件SQL1...4`，不读取新增的`源表-oracle`和`oracle关联拓展事件SQL1...4`。即使复制这些章节，正式计算也不会使用。
5. V10 中部分实体页被替换成“数据链路分析”页，缺少完整可执行 SQL，不能整页覆盖运行实体。

## 二、核查方法

本次逐一比较了 15 个口径在 V10 与运行知识库中的：

- 关联拓展事件 SQL；
- Oracle关联拓展事件 SQL；
- 源表抽取 SQL；
- Oracle源表抽取 SQL；
- 概览、科室和患者明细 SQL；
- SQL块长度与 SHA-256；
- SQL Server专属语法与 Oracle语法标记。

对非空 Oracle候选 SQL进行了真实 Oracle只读试执行：

```text
数据库：当前已启用的 Oracle业务库
方式：内嵌只读数据库工具
统计窗口：2025-01-01 至 2026-01-01
返回限制：最多1行
```

试执行只验证“语法、对象和基本输出能否成立”，不把“查询不报错”误判为业务口径已经验收通过。

## 三、15个口径逐组结果

### 3.1 HXZD-008 系列：5个口径，均未解决

涉及口径：

- `HXZD-008-001`
- `HXZD-008-002_001`
- `HXZD-008-002_002`
- `HXZD-008-003`
- `HXZD-008-004`

V10 增加了4段 `oracle关联拓展事件SQL`，但真实 Oracle结果如下：

| 事件 | V10 Oracle候选结果 | 主要问题 |
|---|---|---|
| `OperationRecord` | 失败 | `ORA-00923`；仍含 `TOP 1`、`DATEDIFF`、`GETDATE`、`STUFF/FOR XML PATH` |
| `PatientRecord` | 失败（原文直跑） | 仍含 `GETDATE`、`ISNULL`、`DATEDIFF` |
| `PreoperativeDisc` | 失败（原文直跑） | 仍含 `ISNULL` |
| `EmrOperationRecord` | 失败（原文直跑） | 仍含 `GETDATE`、`ISNULL` |

其中后三段的简单函数有机会继续由现有方言转换器处理，但第一个 `OperationRecord`仍是本组的确定性阻断点。

V10 的 `源表-oracle`虽然能单独执行，但它不是此前失败的核心层级。HXZD-008 的主源表逻辑读取抽取后的 `MRAS_PATIENT_EVENT`，正式链路仍需保留真实库 SQL Server语义，不能用该 Oracle块替换现有主源表 SQL。

因此本组不能吸收。

### 3.2 HXZD-011 系列：2个口径，候选接近可用但仍不能直接吸收

涉及口径：

- `HXZD-011-001`
- `HXZD-011-002`

两者共用同一段 `源表-oracle`。V10 已将主要字符串聚合改为 `LISTAGG`，但原文真实 Oracle试执行失败：

```text
ORA-00918: 未明确定义列
```

确定原因是同一 SELECT 同时输出了两个 `bizAttrOneName`：

```sql
t11.SURGERY_NAME AS bizAttrOneName
t15.ORG_NAME AS bizAttrOneName
```

前者实际应对应目标表 `SURGERY_NAME`，后者才对应 `BIZ_ATTR_ONE_NAME`。核查时把前者临时改为：

```sql
t11.SURGERY_NAME AS surgeryName
```

修正后 Oracle只读查询能够返回数据，且输出同时具有 `SURGERY_NAME`和`BIZ_ATTR_ONE_NAME`。

但这属于对 V10 候选的二次修复，且尚缺以下正式验收：

- 与原 SQL Server版本的记录数对账；
- 医师、麻醉医师重合与不重合案例对账；
- `LISTAGG`顺序、重复值、空值和超长行为核对；
- 写入 `MRAS_BUSINESS_SURGERY`后的字段类型、长度和重复记录检查；
- 两个关联口径的分子、分母回归。

因此不能把 V10 原文直接吸收到运行知识库。它可以作为下一轮人工修正的底稿。

### 3.3 HXZD-012 系列：8个口径，只完成部分公共片段

涉及口径：

- `HXZD-012-001_001`
- `HXZD-012-001_002`
- `HXZD-012-002_001`
- `HXZD-012-002_002`
- `HXZD-012-003_001`
- `HXZD-012-003_002`
- `HXZD-012-004_001`
- `HXZD-012-004_002`

V10 的实际完成情况：

| 唯一 SQL组 | V10 状态 | Oracle只读结果 | 结论 |
|---|---|---|---|
| 公共事件 `MahpComplication` | 已提供 Oracle候选 | 通过 | 可作为后续底稿 |
| 公共事件 `PatientRecord` | Oracle章节仍含 T-SQL函数 | 原文失败 | 仍依赖方言转换器 |
| 源表组1：`012-001_001`、`012-002_001` | 只在前者提供非空候选 | 前者通过 | 后者章节为空，尚未形成完整复用配置 |
| 源表组2：`012-001_002`、`012-003_002` | 只在前者提供非空候选 | 前者通过 | 后者章节为空，尚未形成完整复用配置 |
| 源表组3：`012-002_002`、`012-004_002` | 空 SQL块 | 未执行 | 未完成 |
| 源表组4：`012-003_001`、`012-004_001` | 空 SQL块 | 未执行 | 未完成 |

“公共事件通过”和“两段源表通过”只能说明部分候选具备继续验证的条件，不能证明8个口径已经可用。当前还缺：

- 将共享 SQL确定性绑定到全部复用口径；
- 补齐源表组3和组4；
- 验证 `PatientRecord`经过方言转换后的实际 Oracle结果；
- 校验写入 `MRAS_BUSINESS_SUR_GRADE`的输出字段、类型和长度；
- 三级、四级手术记录集合及分子分母对账。

因此本组也不能直接吸收。

## 四、程序兼容性问题

V10 新增了以下章节：

```text
源表-oracle
oracle关联拓展事件1
oracle关联拓展事件SQL1
...
oracle关联拓展事件4
oracle关联拓展事件SQL4
```

但当前解析器固定读取：

```text
源表
关联拓展事件1
关联拓展事件SQL1
...
关联拓展事件4
关联拓展事件SQL4
```

所以把 V10 的 Oracle章节原样复制到运行知识库会出现一种危险的“看起来已经配置、实际计算完全没使用”的状态。

后续若正式采用双方言章节，程序至少需要：

1. 同时解析并保存 SQL Server与 Oracle两套业务侧 SQL。
2. 根据当前热切换后的业务库类型选择正确版本，不能只在应用启动时选择。
3. 概览、科室、患者明细仍固定使用真实库 SQL Server版本。
4. Oracle专用章节缺失时明确告警或按可证明的方言转换规则处理，不能静默选错版本。
5. SQL版本、方言和哈希进入抽取快照，切换数据库后旧快照必须失效。

## 五、本次吸收决定

本次执行决定：

```text
运行知识库实体修改：0个
直接吸收的 Oracle SQL：0段
保留为后续修复底稿：
  - HXZD-011 共用源表候选（需先修复重复别名并完成对账）
  - HXZD-012 MahpComplication候选
  - HXZD-012 源表组1候选
  - HXZD-012 源表组2候选
```

不吸收的原因不是“候选完全没有价值”，而是它们目前尚不能在正式链路中确定性生效，且不足以覆盖完整口径。直接写入运行知识库会造成错误的完成状态。

## 六、建议后续顺序

1. 先实现运行时双数据库方言 SQL选择，确保 `源表-oracle`和 Oracle事件章节真正会被使用。
2. 修复并验收 HXZD-011 共用源表候选，可优先恢复2个口径。
3. 补齐 HXZD-008 的公共 `OperationRecord`，一次恢复5个口径。
4. 对 HXZD-012 先固化公共事件，再补源表组3、组4，并把组1、组2复制关系写成确定性配置。
5. 每个唯一 SQL组完成 Oracle业务源记录、真实库写入记录和最终分子分母三级对账后，再吸收到运行知识库。
