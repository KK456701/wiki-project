# Vue 单文件组件行数限制规范（常驻）

> `.vue` 单文件组件总行数应严格控制在 **200 行左右**，绝对不可逾越的硬性上限为 **250 行**。超过必须强制拆分。

## 行数统计规则

- 统计整个 `.vue` 文件的总行数（包括 `<template>`、`<script>`、`<style>` 三个区块）
- 空行和注释行也计入总数

## 强制执行机制

| 行数范围   | 处理方式                      |
| ---------- | ----------------------------- |
| ≤ 200 行   | ✅ 符合规范，无需调整         |
| 201-249 行 | ⚠️ 接近上限，建议优化         |
| ≥ 250 行   | ❌ **强制拆分**，必须立即重构 |

## 拆分策略（按优先级）

### 1. 提取组合式函数（Composables）

将复杂的业务逻辑和状态管理抽离为组合式函数：

```
src/views/{Module}/composables/
├── use{Feature}Data.ts    # 数据获取逻辑
├── use{Feature}Form.ts    # 表单处理逻辑
├── use{Feature}Table.ts   # 表格操作逻辑
└── use{Feature}Auth.ts    # 权限控制逻辑
```

**适用场景**：数据获取和处理逻辑、复杂状态管理、可复用业务逻辑、超过 10 行的事件处理函数。

### 2. 提取子组件

将独立的 UI 区块提取为独立的子组件：

```
src/views/{Module}/components/
├── {Feature}Form.vue      # 表单组件
├── {Feature}Table.vue     # 表格组件
├── {Feature}Dialog.vue    # 弹窗组件
├── {Feature}Card.vue      # 卡片组件
└── {Feature}Filter.vue    # 筛选组件
```

**拆分原则**：每个 UI 区块独立成组件；组件职责单一，可复用；通过 props/emit 通信；模板中超过 30 行的独立区块应考虑提取。

### 3. 提取常量和配置

将静态数据、配置项、类型定义提取到独立文件：

```
src/views/{Module}/
├── constants.ts           # 常量定义（状态映射、选项列表）
├── types.ts               # 类型定义（接口、类型别名）
└── config.ts              # 配置项（表格列配置、表单配置）
```

### 4. 提取样式

如果样式较多（`<style>` 区块超过 50 行），提取到独立的 SCSS 文件：`src/views/{Module}/styles/index.scss`。

## 重构检查清单

- [ ] `.vue` 文件总行数是否 ≤ 200 行（理想）或 ≤ 250 行（硬性上限）
- [ ] 是否有可提取的独立 UI 区块（超过 30 行的模板区块）
- [ ] 是否有可复用的逻辑（超过 10 行的函数）
- [ ] 常量、配置是否已提取到独立文件

## 豁免情况

以下情况可适当放宽限制（但仍应尽量优化）：不可避免的复杂表单（需标注 `// TODO: 考虑拆分`）、主要是表格列定义的展示页（列配置应提取到 config.ts）、重构过程中的临时状态（需标注 `// TODO: 待拆分`）。

## 自动化工具

```bash
# 找出所有超过 200 行的 .vue 文件
find src -name "*.vue" -exec wc -l {} \; | awk '$1 > 200 {print}'
# 找出所有超过 250 行的 .vue 文件（必须拆分）
find src -name "*.vue" -exec wc -l {} \; | awk '$1 >= 250 {print "❌ " $0}'
```

## 禁止的伪优化手段

**核心原则**：行数限制是为了推动代码结构优化，**绝不是**以牺牲可读性为代价压缩行号的数字游戏。以下手段**一律禁止**：

1. ❌ 不得删除必要的代码注释（JSDoc、业务逻辑说明、TODO/FIXME/HACK 标记等）
2. ❌ 不得删除必要的代码空行（逻辑区块之间的空行有助于视觉分组）
3. ❌ 不得将多行 CSS/SCSS 压缩为单行（属性必须保持一行一个、正常缩进）

## 注意事项

1. 不要为了拆分而拆分：拆分的目的是提高可读性和可维护性
2. 保持合理的抽象层级：避免过度抽象导致组件层级过深（建议不超过 3 层）
3. 优先提取逻辑：相比提取子组件，优先提取 composables 可以更有效地减少行数
