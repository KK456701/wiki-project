# 代码格式化规范（按需：编辑 src/**/*.ts / *.vue / *.js / *.scss 后）

> AI 在新增或编辑代码文件后，**必须立即对变更的文件执行格式化命令**，确保代码符合项目统一的格式规范。

## 格式化命令

**仅对变更的文件执行格式化**：

```bash
npx prettier --write <file-path>
```

```bash
# 格式化多个变更文件
npx prettier --write src/views/LoginView.vue src/router/index.ts
```

## 执行时机

1. **新增文件后**：创建新文件并写入内容后，立即对该文件执行格式化
2. **编辑文件后**：修改现有文件内容后，立即对该文件执行格式化
3. **批量操作后**：完成多个文件的编辑后，一次性对所有变更文件执行格式化

## 与其他规则的协作

### 当项目同时存在行数限制规则时（见 `A03-vue-component-size.md`）

**必须先执行格式化，再检查行数**。原因：Prettier 格式化可能将长行拆分为多行，导致文件行数增加；若先检查行数（如 240 行，符合 ≤250 限制），格式化后可能变成 300 行（超出限制）。正确流程：**编写代码 → 执行 Prettier 格式化 → 检查格式化后的行数 → 如超限则拆分**。

### 当格式化命令执行失败时

1. 检查文件语法是否正确（Prettier 无法格式化语法错误的文件）
2. 修复语法错误后重试格式化
3. 如果格式化持续失败，**不要跳过**，应报告错误并等待人工处理

## 为什么不对全量文件执行

`npm run format`（`prettier --write src/`）会扫描 `src/` 下所有文件。仅格式化变更文件更高效，尤其在项目文件较多时。

## 格式化范围

- TypeScript 文件（`.ts`）
- Vue 单文件组件（`.vue`，含 `<style lang="scss">` 块）
- JavaScript 文件（`.js`）
- SCSS 文件（`.scss`）

> 提示：格式化只解决"格式"问题，不解决"质量"问题。修改代码后还应执行 `npm run lint` 与 `npm run typecheck` 做质量与类型校验，详见 `A02-verification-gate.md`。

## 验证方法

```bash
npm run format:check
```

## 注意事项

1. **不要跳过格式化**：即使代码看起来已经格式化，也必须执行命令确保一致性
2. **不要手动格式化**：依赖 Prettier 自动格式化，不要手动调整格式
3. **仅格式化变更文件**：不要使用 `npm run format` 对全量文件格式化，除非确实需要

## 检查清单

- [ ] 格式化命令是否成功执行（无错误输出）
- [ ] 代码格式是否符合项目规范
