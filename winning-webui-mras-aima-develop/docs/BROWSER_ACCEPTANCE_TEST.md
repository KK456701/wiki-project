# 医疗核心制度指标系统全量浏览器验收手册

> 适用对象：医院实施人员、开发人员、负责真实浏览器验收的 AI。
> 前端地址：`http://127.0.0.1:8675/webui-mras-aima/`
> 后端地址：`http://127.0.0.1:8765/`
> 验收原则：只认页面实际结果、接口响应和浏览器控制台证据，不用代码推断代替浏览器操作。

## 1. AI 执行指令

执行本手册时必须遵守以下规则：

1. 使用真实浏览器逐项点击，不通过直接调用前端函数来冒充验收。
2. 每个用例记录：用例编号、时间、账号/医院、输入、页面结果、关键接口状态、控制台错误、截图路径、结论。
3. 所有涉及指标数据的用例优先使用 `2025-01-01 至 2025-12-31`，避免当前年份尚无数据造成误判。
4. 页面显示错误编号时，完整记录错误编号；不得把真实错误改写成“网络异常”或“表结构错误”。
5. 不得执行写 SQL。页面“执行 SQL”只允许只读查询；出现写操作、动态 SQL、临时表或多语句时应验证系统会拦截。
6. “保存草稿”“清空日志”等会改变状态的操作，只在本地测试案例中执行，并完成二次确认验证。
7. 任一 P0/P1 问题出现时先保存证据，再继续执行与故障无依赖的用例；不得因一个失败跳过整份文档。
8. 每完成一个页面，刷新页面验证状态恢复；涉及历史记录的功能还要关闭并重新打开对应页面验证持久化。
9. 最终输出通过率、失败清单、阻塞清单、错误编号清单、控制台错误清单和建议回归范围。

严重级别：

- P0：页面白屏、数据串院、执行写 SQL、正式数据被误改、主要流程完全不可用。
- P1：指标计算/异常排查结果错误、患者明细错配、报告为空、关键按钮卡死。
- P2：单个辅助功能失败、错误文案与真实原因不一致、刷新后状态丢失。
- P3：样式、间距、图标、非关键提示等体验问题。

## 3. 环境与通用能力

### PRE-001 服务与资源

- 打开前端根地址，确认自动进入聊天页。
- Network 中确认入口 HTML、JS、CSS 均为 200，资源哈希与本次构建一致。
- 请求后端健康接口，确认 8765 可达。
- 页面不得出现 502、白屏、无限加载或旧哈希资源混用。

### PRE-002 身份与医院隔离

- 记录当前医院、用户、会话标识。
- 用另一医院或无权限身份读取当前会话、排查案例、患者明细和导出文件，预期返回 403/404，而不是患者数据。
- URL 中替换其他 `caseId`、`conversationId`、`exportId`，预期无法越权读取。

### PRE-003 全局错误边界

- 断开后端后刷新一次，确认页面显示可理解的降级错误而不是白屏。
- 恢复后端并点击“刷新页面”，确认页面恢复。
- 低版本/非安全上下文浏览器中验证生成客户端 ID 不依赖 `crypto.randomUUID`，患者澄清不得导致整页崩溃。

### PRE-004 响应式与键盘

- 分别在 1920×1080、1366×768、窄屏宽度验收聊天、排查、明细和弹窗。
- Tab 可到达主要按钮；Enter 可发送；Esc 可关闭普通弹窗；焦点不得丢到页面背后。
- 表格列较多时必须可横向滚动，列头和单元格不得被强制压成不可读文字。

## 4. 主聊天页 `/chat`

### CHAT-001 会话侧栏

- 点击左上菜单展开/收起侧栏。
- 点击“新对话”，确认产生新会话并清空当前输入区。
- 连续创建两条会话，在列表间切换，确认各自消息不串线。
- 删除一条测试会话：验证取消、确认删除、删除后路由和选中项更新。
- 刷新页面，确认保留的会话和消息可恢复。

### CHAT-002 顶部工具

- 切换亮色/暗色主题，刷新后检查主题是否符合产品当前持久化规则。
- 打开“标注说明”，检查内容和关闭按钮。
- 打开“系统设置”抽屉，再关闭。
- 点击顶部“新对话”，行为应与侧栏新建一致。

### CHAT-003 输入、模型和停止

- 打开模型菜单，逐项检查名称、供应商、可用状态，选择一个可用模型。
- 发送“患者入院48小时内转科的比例怎么计算”，确认用户消息立即出现，助手出现流式状态并最终回复。
- 生成过程中点击停止，确认按钮动态变为停止态、请求终止、页面可继续发下一条。
- 快速双击发送，确认不会重复提交同一请求。
- 复制助手回复，确认剪贴板内容完整。

### CHAT-004 快捷入口“算指标”

- 点击“算指标”，选择一个指标、多个指标、全选和取消全选。
- 验证指标搜索、清空、删除单个 Chip。
- 验证本月、上月、本季度、上季度、今年、去年六个快捷周期和手工日期范围。
- 未选指标或时间时“开始计算”禁用。
- 选择 `HXZD-001-001` 和 2025 全年，点击“开始计算”，确认发送的提示词包含真实指标名称和完整周期。
- 计算过程中验证步骤状态动态变化，不得一直显示一个模糊的“执行中”。

### CHAT-005 快捷入口“查故障”与异常意图

- 点击“查故障”，应直接进入 `/diagnosis?step=selection` 空白第一步，不创建旧 Demo 卡片。
- 在聊天输入“这个指标算多了，帮我异常排查”，确认收到简短跳转回复，SSE 正常结束后才导航。
- 在聊天输入普通“计算全部指标”请求，即使某些指标结果异常，也不得误判为异常排查跳转。
- 置信度不足时应先追问，不得擅自跳转。

### CHAT-006 时间澄清

- 发送不带周期的计算请求，确认只出现一次时间澄清。
- 选择/确认时间后，下一条请求必须携带所选周期并继续原任务。
- 连续点击确认不得反复出现同一个时间问题。
- 点击忽略后输入新请求，不得继续复用已忽略的旧澄清。

### CHAT-007 批量计算结果

- 验证任务总数、成功、失败、跳过和耗时。
- 打开执行步骤抽屉，切换任务、节点，检查状态、真实错误和错误编号。
- 点击“质量复核”“检查清单”等已显示动作，确认加载、成功、失败三种状态可见。
- 成功指标必须在完整报告中存在；部分失败时完整报告仍展示成功任务。

### CHAT-008 完整报告与 Word 导出

- 打开“查看完整报告”，确认完全由 `reportSnapshot.tasks` 渲染。
- 核对指标编码包含完整口径后缀（如 `HXZD-008-002_001`）。
- 核对指标导向、异常范围初筛、目标值、结果、分子/分母及失败原因。
- 下载 Word，打开文件核对标题、表格、中文、口径后缀和失败项。
- 关闭再打开报告，数据不得变为空。

### CHAT-009 口径、链路和 Trace

- 在报告任务行分别打开口径、链路、明细。
- 口径弹窗切换“基本信息与契约”“SQL 模板”，复制 SQL，关闭弹窗。
- 打开数据流图，点击各节点、展开 SQL、复制 SQL、执行只读 SQL。
- 打开 Trace 详情，复制 JSON；点击“查看链路”进入独立 Trace 页。

## 5. 统一指标明细和 Excel

### DETAIL-001 普通比率 `COUNT_RATIO`

- 使用 `HXZD-001-001` 2025 全年结果。
- 打开分子、分母、差异三个页签；首页卡片不单独展示“未进入分子”数字。
- 验证 `分母条数 = 分子条数 + 差异条数`，按统计记录/就诊人次计算，不按姓名去重。
- 验证姓名/编号搜索、科室筛选、重置、上一页、下一页和横向滚动。
- 字段存在中文映射时必须显示中文列名。

### DETAIL-002 求和 `SUM_CONTRIBUTION`

- 使用 `HXZD-007-001`。
- 只展示贡献明细；每行含分子贡献、分母贡献，汇总值与指标卡一致。
- 不得伪造分子/分母患者页签。

### DETAIL-003 中位数 `MEDIAN_SAMPLE`

- 使用 `HXZD-014-001`。
- 展示有效样本、样本值、排名、样本总数。
- 奇数标记一条中位记录；偶数标记两条，并显示平均值与卡片一致。

### DETAIL-004 双数据源 `DUAL_SOURCE`

- 使用 `HXZD-012-004_001`。
- 展示实际开展明细和备案目录明细。
- 没有可靠关联键时不得出现虚假的差异页签或错误患者匹配。

### DETAIL-005 两率对比 `RATE_COMPARISON`

- 验证四级命中、四级母集、四级未命中、三级命中、三级母集、三级未命中六组。
- 每组数量与指标计算语义一致，详情 ID 稳定，翻页不得重复/漏行。

### DETAIL-006 Excel 导出

- 点击“导出明细 Excel”，验证患者数据安全确认的取消和确认。
- 无权限用户应被拒绝；有权限用户只能下载当前医院快照。
- 打开工作簿，核对摘要页、快照编号、结果、各组数量和工作表行数。
- 页面查看和 Excel 必须复用同一快照；刷新业务数据后不得一边旧一边新。
- 超过 20,000 行时应明确拒绝并提示缩短周期，不得生成被静默截断的文件。

## 6. 异常排查第一步 `/diagnosis?step=selection`

### DIAG-SEL-001 选择指标与口径

- 验证指标搜索和单选。
- 选中指标后验证口径列表只包含该指标口径；切换指标后旧口径清空。
- 使用 `HXZD-008-002` 检查 `_001/_002` 两个口径可区分。
- 验证手工周期和所有快捷周期；日期结束边界应覆盖当天 23:59:59 或等价半开区间。
- 三项未完整时“开始排查”禁用；完整后点击并进入第二步。

### DIAG-SEL-002 刷新与 URL

- 第二步刷新后案例可恢复。
- 删除 URL 中 `caseId` 或传无效 ID，页面应回到可理解状态，不得读取上一案例患者数据。
- 点击右上关闭，验证返回聊天页。

## 7. 异常排查第二步“数据确认”

### DIAG-DATA-001 三步基础校验

- 依次观察表结构、事件与抽取、数据可用性三项状态。
- 任一项运行中要显示当前动作；失败时保留真实错误和错误编号。
- 第二项失败的建议统一显示“请人工检查是否有重复事件启用”，但不能覆盖原始失败事实。
- 点击重试，确认只重跑正确范围且按钮防重复。

### DIAG-DATA-002 结果摘要与明细

- 核对指标结果、分子、分母同一行显示且数值与批次一致。
- 点击分子/分母“查看明细”，检查统一明细弹窗、中文字段和横向滚动。
- 搜索、筛选、分页、Excel 导出与第 5 章一致。

### DIAG-DATA-003 AI 初筛

- 展开/收起 AI 初筛，等待动态状态完成。
- 验证疑似姓名、科室、重复业务编号的命中和明细。
- 点击重试，旧请求应取消，不能显示 `signal is aborted without reason`。
- 点击“一键修复”，打开方案和差异比较；完整候选 SQL 可展开、复制和执行。
- 未生成或未修改候选 SQL 时，候选整体执行按钮必须禁用；正式链路整体执行仍可用。

### DIAG-DATA-004 助手介绍和历史问题案例

- 初始介绍、历史问题分类块和输入区正常显示。
- 分类块白底、选中蓝色，文字为“口径问题案例”等，不显示数量尾缀或箭头。
- 打开分类弹窗，核对 TFS 单号、日期、处理人；展开问题描述、根因、处理方案。
- 关闭弹窗，确认不创建对话、不改变案例状态。

### DIAG-DATA-005 历史对话独立下拉

- 点击标题栏“历史对话 N”，列表必须悬浮在独立下拉层，不挤压或缩放助手主体。
- 最多显示一条“患者澄清”和一条“自主排查”；点击后恢复对应完整历史并直接进入可继续对话状态。
- 患者澄清历史恢复后可继续选择患者并追加问答；自主排查历史恢复后可继续输入追问。
- 只有案例已结束并进入只读状态时才隐藏输入能力；刷新后历史仍存在。
- 下拉在桌面和窄屏都能滚动，点击外部关闭，不遮死输入框。

### DIAG-DATA-006 患者澄清连续会话

- 点击“患者澄清”，助手主体保持固定尺寸，患者选择器向上展开。
- 分别选择“统计多了”“统计少了”，验证方向切换。
- 验证患者下拉可直接浏览，也可按姓名/床位号、住院号/入院日期、就诊 ID、姓名/住院号搜索。
- 选中患者后提示词进入输入框；点击发送后用户气泡立即出现，随后显示思考/停止和回复。
- 连续澄清两个不同患者：当前区域按“问题、回复、问题、回复”连续追加，不创建第二条患者历史会话。
- 刷新页面并从历史下拉打开患者澄清，必须看到两轮完整消息和各自核验证据。
- “统计多了”按分子→分母→中间表→业务源解释；在分子时优先解释分子。
- “统计少了”按 Oracle 业务源→中间表→分母→分子定位首次消失层级。
- 点击发送后的方形停止按钮，确认本轮停止且此前对话保留；不得出现独立红色停止按钮。

### DIAG-DATA-007 生成排除 SQL

- “生成排除科室后的 SQL”向上展开科室下拉，选择后直接进入第三步并带入条件。
- “生成排除患者后的 SQL”向上展开患者下拉，搜索和选择后直接进入第三步。
- 两个快捷操作不创建助手历史对话。
- 自主排查运行中触发上述操作时，应先停止自主任务并标记切换原因，旧任务不得回写过期候选 SQL。

### DIAG-DATA-008 AI 自主排查

- 点击后显示自主排查介绍，输入问题并发送。
- 用户消息立即出现；发送键变为方形停止键。
- 思考和工具调用以事件顺序显示，运行时自动滚动到最新内容，完成后自动收起。
- 手工再次展开后必须保留原始思考/工具内容。
- 完成回复只展示自然语言结论，不展示原始 JSON。
- 追问时形成连续问答；运行中再次点击快捷入口只打开当前任务，不重复创建。
- 完成、失败或停止后再次启动才创建新的自主排查历史。

### DIAG-DATA-009 输入框意图引导

- 输入问候，助手在同一对话区域回复问候/能力引导。
- 输入患者核验意图，回复引导点击“患者澄清”。
- 输入排除患者/科室 SQL 意图，回复引导点击对应快捷入口。
- 输入无法处理的问题，回复“抱歉，暂时无法处理这类请求”，并建议自主排查。
- 不得自动展开选择器，不得把回复放在灰色警告块里。

### DIAG-DATA-010 结束和进入链路

- 点击“确认无异议”，验证取消和确认；确认后案例只读。
- 点击“进入数据链路核查”，进入第三步并保留当前案例。
- 步骤条只能导航到允许访问的步骤，不能跳过必需状态。

## 8. 异常排查第三步“数据链路核查”

### DIAG-LINE-001 图与节点

- 等待链路图加载；点击“适应画布”，验证节点完整可见。
- 逐个点击源表抽取、概览、科室、患者、事件等实际存在节点。
- 节点详情、数据库类型、表、输入输出、运行配置和警告与链路一致。
- 展开/收起 SQL、复制 SQL；Oracle 和 SQL Server 展示方式应与各自方言一致。

### DIAG-LINE-002 SQL 编辑和 AI 生成

- 切换“直接编辑 SQL”和“AI 生成对应 SQL”。
- 未修改 SQL 时保存/候选执行应禁用；修改后保存状态可见。
- 输入排除条件后生成候选 SQL，检查差异行、完整 SQL 展开和复制。
- 时间参数不得一边写死日期、一边要求占位符；显示与校验契约必须一致。

### DIAG-LINE-003 整体执行与候选结果

- 没有候选修改时执行当前正式链路；存在已保存候选时优先执行候选链路。
- 按钮依次显示校验、查询 Oracle/SQL Server、整理结果等动态文字。
- 结果展示指标值、正式值、差异、差异明细；不得错误显示候选分子/分母明细。
- 展开差异患者，数据必须来自本次候选链路而不是旧 SQL Server 缓存。

### DIAG-LINE-004 草稿

- 打开保存草稿表单，验证取消。

## 9. 共享只读 SQL 执行

### SQL-001 可执行入口覆盖

- 在聊天数据链路、异常排查各节点、初始化校验、AI 初筛正式/候选 SQL、知识审批等实际出现 SQL 的位置查找“执行 SQL”。
- 普通聊天代码块、JSON 和日志不得出现执行入口。
- 无法判断数据库或统计周期时按钮禁用并显示具体原因。

### SQL-002 成功、空结果和分页

- 分别执行一个 Oracle 源表 SQL 和一个 SQL Server 统计 SQL。
- 验证数据库、耗时、总行数、前 200 行、截断提示、分页和实际执行 SQL。
- 执行零行查询，显示明确空状态而不是失败。
- 复制实际 SQL，核对参数已经正确绑定且不泄漏凭据。

### SQL-003 安全拦截

- 验证 INSERT/UPDATE/DELETE/MERGE/DDL、SELECT INTO、FOR UPDATE、动态 SQL、临时表、外部数据源、多语句均被拦截。
- 验证 30 秒超时显示真实超时原因。
- 连续点击执行只产生一个请求；执行期间按钮文字持续更新。
- 普通日志和 Trace 不得记录患者行或完整 SQL 明文。
