## 高能力模型

### 特征

- 可处理模糊描述和隐含信息
- 具备较强的上下文推断能力
- 可自动补全常见默认值
- 支持复杂的多步推理

### 示例模型

| 模型名称 | 提供商 | 备注 |
|---------|--------|------|
| deepseek-v4 | DeepSeek | 强推理能力 |
| glm-5.2 | 智谱 AI | 中文理解强 |
| qwen-max | 阿里云 | 综合能力强 |
| gpt-4o | OpenAI | 多模态支持 |
| claude-3.5 | Anthropic | 长上下文 |

### 信息密度要求

| 检查项 | 是否必需 | 说明 |
|--------|---------|------|
| 统计周期 | ✅ | 必须明确 |
| 报告类型 | ✅ | 必须明确 |
| 输出路径 | ⚠️ | 可用默认值 `report/` |
| 数据来源 | ⚠️ | 可从上下文推断或询问 |
| 目标值 | ⚠️ | 可自动查询目标表 |
| 科室范围 | ⚠️ | 可默认全部科室 |
| 报告层级 | ⚠️ | 可默认包含全部层级 |

### 检查清单模板

```markdown
## 缺失信息

### 必须确认
- [ ] 统计周期：{周期}
- [ ] 报告类型：{类型}

### 可自动推断（如需修改请说明）
- 输出路径：`report/{filename}.md`
- 数据来源：从数据库实时查询
- 目标值：从 MRAS_TARGET_DEFINITION 查询

如需调整默认配置，请告知。
```

## 中能力模型

### 特征

- 需要明确的数据来源和统计口径
- 可处理部分结构化数据
- 需要清晰的步骤指引
- 对隐含信息理解有限

### 示例模型

| 模型名称 | 提供商 | 备注 |
|---------|--------|------|
| qwen-plus | 阿里云 | 性价比较高 |
| gpt-4o-mini | OpenAI | 轻量版 |
| deepseek-v3 | DeepSeek | 上一代 |
| glm-4 | 智谱 AI | 上一代 |
| llama-3.1-70b | Meta | 开源大参数 |

### 信息密度要求

| 检查项 | 是否必需 | 说明 |
|--------|---------|------|
| 统计周期 | ✅ | 必须明确 |
| 报告类型 | ✅ | 必须明确 |
| 输出路径 | ✅ | 必须明确 |
| 数据来源 | ✅ | 必须明确（数据库 or 文件） |
| 目标值 | ✅ | 必须提供具体数值或编码 |
| 科室范围 | ⚠️ | 可默认全部，但需说明 |
| 报告层级 | ✅ | 必须明确选择 |

### 检查清单模板

```markdown
## 缺失信息

### 必须提供
- [ ] 统计周期：开始日期、结束日期
- [ ] 报告类型：确认事件编码
- [ ] 输出目录和文件名格式

### 数据来源（二选一）
- [ ] 数据库连接字符串
- [ ] 已导出的数据文件路径

### 目标值
- [ ] 目标值编码（如 `HXZD-001-001`）
- [ ] 或具体目标值（如 `2.5%`）

### 报告内容（请选择）
- [ ] 概览层（汇总值 + 目标对比）
- [ ] 科室层（按科室拆分）
- [ ] 明细层（逐患者记录）
```

## 低能力模型

### 特征

- 需要完整、精确的结构化数据
- 推断能力较弱
- 需要明确的步骤和格式
- 对模糊描述容易出错

### 示例模型

| 模型名称 | 提供商 | 备注 |
|---------|--------|------|
| llama-3.1-8b | Meta | 本地部署 |
| qwen2.5-7b | 阿里云 | 本地部署 |
| glm-4-9b | 智谱 AI | 本地部署 |
| mistral-7b | Mistral | 本地部署 |
| phi-3.5 | Microsoft | 小参数 |

### 信息密度要求

| 检查项 | 是否必需 | 说明 |
|--------|---------|------|
| 统计周期 | ✅ | 必须精确到日 |
| 报告类型 | ✅ | 必须明确事件编码 |
| 输出路径 | ✅ | 必须完整路径 |
| 数据来源 | ✅ | 必须完整连接串或文件 |
| 目标值 | ✅ | 必须具体数值 |
| 科室范围 | ✅ | 必须明确列表 |
| 报告层级 | ✅ | 必须明确选择 |
| 分子定义 | ✅ | 必须精确描述 |
| 分母定义 | ✅ | 必须精确描述 |

### 检查清单模板

```markdown
## 缺失信息（全部必须提供）

### 1. 统计周期
- [ ] 开始日期：YYYY-MM-DD
- [ ] 结束日期：YYYY-MM-DD

### 2. 报告类型
- [ ] 事件编码：如 `CORE_FDR`
- [ ] 指标名称：如 `患者入院48小时内转科的比例`

### 3. 输出配置
- [ ] 输出目录：如 `report/`
- [ ] 文件名格式：如 `{yyyy_MM_dd-HH_mm_ss}.md`

### 4. 数据来源（二选一）
- [ ] 数据库连接：`Server=xxx;Database=xxx;User=xxx;Password=xxx;`
- [ ] 数据文件：完整路径，如 `data/fdr_data.csv`

### 5. 目标值
- [ ] 目标值编码：如 `HXZD-001-001`
- [ ] 或具体数值：如 `2.5`（百分比）

### 6. 统计口径
- [ ] 分子定义：入院48小时内转科患者人次数
- [ ] 分母定义：同期入院患者总人次数

### 7. 科室范围
- [ ] 全部科室：是/否
- [ ] 如否，请提供科室编码列表

### 8. 报告内容（必须选择）
- [ ] 概览层：是/否
- [ ] 科室层：是/否
- [ ] 明细层：是/否

## 数据格式要求

如果使用文件导入，请确保数据包含以下字段：
- `ENCOUNTER_ID`：住院 encounter ID
- `CURRENT_DEPT_ID`：科室编码
- `CURRENT_DEPT_NAME`：科室名称
- `ADMITTED_TO_WARD_AT`：入区时间
- `TRANSFER_WITHIN_TWO_DAY`：是否48小时内转科（98175=是，98176=否）
```

## 信息密度矩阵

### 检查项 × 模型等级

| 检查项 | 高能力 | 中能力 | 低能力 |
|--------|--------|--------|--------|
| 统计周期 | 必需 | 必需 | 必需 |
| 报告类型 | 必需 | 必需 | 必需 |
| 输出路径 | 可推断 | 必需 | 必需 |
| 数据来源 | 可推断 | 必需 | 必需 |
| 目标值 | 可查询 | 必需 | 必需 |
| 科室范围 | 可默认 | 需说明 | 必需 |
| 报告层级 | 可默认 | 必需 | 必需 |
| 分子定义 | 可推断 | 需确认 | 必需 |
| 分母定义 | 可推断 | 需确认 | 必需 |
| 数据格式 | 可推断 | 需说明 | 必需 |

### 信息量对比

| 模型等级 | 最少信息量 | 推荐信息量 |
|---------|-----------|-----------|
| 高能力 | 2 项（周期+类型） | 3-4 项 |
| 中能力 | 5 项 | 7-8 项 |
| 低能力 | 10+ 项 | 全部提供 |

## 使用指南

### 如何确定模型等级

1. 查看当前使用的模型名称
2. 对照上方模型列表确定等级
3. 如不在列表中，按以下规则判断：
   - 参数 ≥ 70B 或商业旗舰模型 → 高能力
   - 参数 7B-70B 或商业标准模型 → 中能力
   - 参数 < 7B 或本地小模型 → 低能力

### 如何输出适配的检查清单

1. 确定当前模型等级
2. 复制对应的检查清单模板
3. 填充已知信息
4. 标注缺失项的优先级
5. 提供明确的下一步操作指引
